# AI IMPLEMENTATION PROTOCOL

## Purpose

This document defines the mandatory implementation process that must be followed during the entire DairySphere project.

Every future implementation must comply with this document.

If another instruction conflicts with this protocol,

stop and report the conflict.

Never continue by making assumptions.

---

# Core Principles

Always prefer correctness over speed.

Always protect existing functionality.

Always preserve data integrity.

Always preserve financial history.

Always preserve project consistency.

Never perform unnecessary changes.

Never rewrite unrelated code.

Never redesign existing architecture without approval.

Never bypass validations.

Never hide errors.

Never suppress errors.

Never use temporary fixes.

Never use shortcuts.

Never use placeholder implementations.

Never generate demo or mock data.

---

# Mandatory Workflow

Every implementation must follow this order.

1. Read all required project documentation.

2. Analyse the existing codebase.

3. Understand project structure.

4. Identify affected modules.

5. Identify affected files.

6. Analyse dependencies.

7. Detect conflicts.

8. Create an implementation plan.

9. Implement only the approved task.

10. Validate implementation.

11. Verify no regression.

12. Report completed work.

13. Stop.

Never continue automatically.

---

# Before Modifying Code

Always understand why the code exists.

Never rewrite working code without approval.

Never duplicate existing logic.

Never duplicate existing validation.

Never duplicate database relationships.

Never create parallel implementations.

Reuse existing architecture whenever possible.

---

# Database Rules

Database integrity has highest priority.

Never break relationships.

Never lose historical records.

Never change financial history.

Never redesign approved schema without approval.

Protect transactional consistency.

---

# Error Resolution

Never hide errors.

Never silence errors.

Never ignore warnings that indicate incorrect implementation.

Find the root cause before changing code.

Fix root causes instead of symptoms.

If the root cause cannot be identified,

stop and report.

---

# Scope Control

Only perform the requested task.

Never implement future phases.

Never add improvements outside the approved scope.

Never add "recommended" features.

Never use industry assumptions.

Only implement documented requirements.

---

# Validation

Before finishing verify:

✓ Documentation was followed.

✓ Scope was respected.

✓ No unrelated files were modified.

✓ Existing functionality remains intact.

✓ No duplicate implementation exists.

✓ No assumptions were introduced.

---

# Final Rule

This protocol is mandatory for every future implementation.

Every future implementation must begin by reading this document before making any change.
